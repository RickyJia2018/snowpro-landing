# 购买前端修复

检查范围仅限网站前端的 SnowCoin 与 Carpool Pass，配合 SnowPro Flutter 的构建分流。未修改后端，未部署或进行真实扣款。

- Token / Pass 使用不同短期会话存储，避免用途与账号交叉；App 一次性链接只从 URL fragment 读取并立即清理。
- 新 Pass 链接兑换时清除旧账号购买会话；兑换失败不回退旧身份；React StrictMode 不会重复消费一次性链接。
- 购买增加同步互斥和请求超时，重定向期间保持锁定；过期会话不能继续购买。
- 两种购买都严格检查 Stripe Hosted Checkout 地址；拒绝非 HTTPS、非精确域名、携带用户名密码的链接。
- 延迟返回的旧账号请求不能恢复已退出的用户或替新账号发起跳转。
- 不向用户显示服务器原始异常、堆栈或内部 URL；无效商品 ID、金额不会被当成免费商品展示。
- Pass 从商品目录接口读取套餐、月数、金额和推荐项，不再硬编码套餐或价格。优先保留 App 指定的有效套餐，否则选择推荐项或首项；加载失败可重试，失败期间禁止支付。
- 目录校验拒绝重复 ID、空 ID、非法金额/月数和错误类型，防止 protobuf 缺省值或异常 JSON 变成有效商品。
- Token / Pass 支持网页账户登录，通过一次性 code 换取用途隔离的短期令牌；不保存密码或完整登录令牌，充值会话缺少用户信息时直接失败。导航增加两种购买入口。
- Pass 返回页不把访问页面视为付款成功。网页没有新增或猜测后端付款确认接口，到账仍需现有服务确认。
- 移除未使用的 Gemini 密钥构建注入配置；前端购买流程不需要该密钥。

验证：48 个测试通过，TypeScript 检查及 Vite 生产构建通过。支付账号归属、Stripe 真正完成付款后的到账，以及 App 回跳需要测试环境联调；本次未声称验证生产交易。

## 2026-09-27 充值恢复队列并发修复

`RechargePage.checkPendingOrder` 原先在开始时读取整个队列，在所有异步核验结束后用旧快照中的剩余记录覆盖存储。核验等待期间新增的 Checkout 会被覆盖删除，丢失前端恢复线索。现改为逐笔移除当前账号已经确认成功的记录；未完成、鉴权过期和暂时失败的记录原地保留。每笔核验前后检查当前登录会话，避免切换账号后继续使用旧身份。

新增页面级测试在旧订单请求悬而未决时加入新 Checkout，分别返回 200/400/401/403/404/500，验证新记录始终保留、原记录按结果处理，另一账号的同编号记录不被清除。只清理当前账号队列，不将其作为修改钱包或认定支付成功的依据。后端仍是资金与订单状态的权威来源。

验证：全部网站测试 61 项通过，TypeScript 检查和 Vite 生产构建通过；输出 `/tmp/recharge-queue-all-tests.log`、`/tmp/recharge-queue-types.log`、`/tmp/recharge-queue-build.log`。未部署、未执行实际购买，也未更改价格、退款资格或账户权限。

此外，不再把 400/403/404 的核验拒绝当作付款已交付或退款证明而删除凭证；例如 403 也可能只是当前账户受限。请求仍有超时和有限队列边界，保留记录供后续核验，不会因拒绝再次发起扣款。
